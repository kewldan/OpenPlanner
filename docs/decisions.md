# Архитектурные решения

Журнал принятых решений. Каждое решение — дата, суть, следствия.

## 2026-11-01 · Распознавание скана — локально, в MVP

Импорт скана Polycam (GLB/ZIP, LiDAR) с автоматическим распознаванием стен, проёмов и комнат входит в MVP. Обработка выполняется на машине пользователя, без сервера.

Следствия:
- Нужен производительный вычислительный модуль для облака точек (~1–2 млн точек): сегментация плоскостей, поиск стен, замыкание контуров, проёмы.
- Мастер импорта: Файл → Обработка → Проверка (сомнительные места с уверенностью) → Параметры. При неудаче: подложка для обводки или пустой проект.

## 2026-11-01 · Импорт из Remplanner — только через их открытый экспорт

Свой парсер закрытого формата `.plan` не пишем (clean room). Перенос проекта возможен через файлы, которые Remplanner выгружает сам (DXF, glTF), и через подложку-изображение.

## 2026-11-01 · Лицензия: AGPL-3.0 + MIT для формата

- Приложение и ядро: AGPL-3.0.
- Схема формата `.oplan` и SDK для работы с ним: MIT.
- Разрешены зависимости под MIT/Apache/BSD/MPL/LGPL/GPL-3.0+. Запрещены GPL-2.0-only (например, LibreDWG).

## 2026-11-01 · Платформа: Tauri 2 + веб-UI + Rust-ядро

- Оболочка: Tauri 2 (macOS, Windows, Linux).
- Интерфейс: TypeScript, веб-фреймворк (выбор отдельно), холст на WebGL2, WebGPU там, где он доступен.
- Ядро на Rust: модель, геометрия, распознавание скана, экспорт (PDF, DXF, XLSX, IFC). В десктопе работает нативно и многопоточно, для веб-версии собирается в WASM.

Следствия:
- Фронтенд не зависит от Tauri напрямую, а работает через тонкий слой платформы. Если вебвью на Linux (WebKitGTK) станет проблемой, можно перейти на Electron без переписывания фронта и ядра.
- Фотореалистичный рендер позже можно вынести в отдельный нативный процесс.

## 2026-11-01 · Основной стиль UI — плотный

Один плотный интерфейс (в духе Figma и Linear) на все режимы. Отдельный «дружелюбный» режим не делаем. Онбординг строим на пустых состояниях, подсказках в статус-строке и стартовом экране.

## 2026-11-01 · Стадии вместо MVP

Работа идёт стадиями (см. `product-spec.md`). Каждая стадия доводится до рабочего состояния. Урезанного MVP нет.

## 2026-11-01 · Интерфейс: React

Панели, инспекторы, таблицы, диалоги пишем на React + TypeScript. Холст фреймворком не рисуется.

## 2026-11-01 · Модель проекта живёт в Rust-ядре

Ядро — источник истины: документ, команды, отмена/повтор, варианты, производные данные (помещения, площади, трассы, объёмы сметы). Фронтенд отправляет команды и получает диффы. Временную графику во время перетаскивания рисует рендерер, без коммита в модель.

## 2026-11-01 · Один рендерер на wgpu (2D и 3D)

- 2D-план, облако точек скана и 3D-вид рисует один рендерер на Rust + wgpu.
- Рендерер собирается в WASM и рисует в `<canvas>` вебвью. Бэкенд — WebGPU там, где он есть, иначе WebGL2.
- Линии постоянной толщины, штрихи и штриховки — в шейдерах. Тесселяция — lyon. Текст — MSDF.
- Ограничение: в режиме WebGL2 нет compute-шейдеров. Всё, что от них зависит, должно иметь CPU-путь.
- Тяжёлый оффлайн-рендер (очередь фотореалистичных кадров) позже можно вынести в нативный wgpu-процесс без окна.

## 2026-11-01 · Файл проекта `.oplan` — ZIP-контейнер

- Внутри: манифест с версией формата, модель (JSON), бинарные данные скана, превью, рендеры, ресурсы.
- Модель читаемая и диффится. Схема публикуется под MIT.
- Автосохранение пишет журнал изменений рядом с файлом и периодически пересобирает контейнер.

## 2026-11-01 · Основная ОС — macOS

Разработка и ручное тестирование — в первую очередь на macOS (WKWebView). Windows и Linux собираются и проходят тесты в CI.

## 2026-11-01 · Ядро и рендерер — один WASM-модуль в Web Worker

```
Вебвью
 ├─ UI-поток: React
 │     ↕ postMessage (команды → ядро; диффы и выборки → панели)
 └─ Web Worker: WASM [ядро модели + wgpu-рендерер] → OffscreenCanvas
Tauri (нативный Rust)
 └─ сервисы: файловая система, .oplan, распознавание скана, экспорт PDF/XLSX/DXF/IFC
```

- Геометрия попадает из модели на GPU без сериализации. UI-поток не блокируется.
- Ядро и сервисы — одни и те же crates. Они компилируются в WASM (воркер, веб-версия) и нативно (Tauri, CLI, тесты).
- В веб-версии нативные сервисы заменяются WASM-реализациями или File System Access API.

## 2026-11-01 · Вход скана: LiDAR-сетка/облако + Room-данные

- Если экспорт содержит параметрические стены и проёмы (Room-режим, Apple RoomPlan), используем их как сильную подсказку.
- Основной путь — свой геометрический конвейер по LiDAR-сетке или облаку точек: пол и потолок → вертикальные плоскости → линии стен на плане → проёмы → замкнутые контуры комнат. Каждый вывод получает оценку уверенности.
- Скан сохраняется в `.oplan` и служит подложкой в 2D и 3D.
