# Архитектурные решения

Журнал принятых решений. Каждое решение — дата, суть, следствия.

## 2026-11-01 · Распознавание скана — локально, в MVP

Импорт скана Polycam (GLB/ZIP, LiDAR) с автоматическим распознаванием стен, проёмов и комнат входит в MVP. Обработка выполняется на машине пользователя, без сервера.

Следствия:
- Нужен производительный вычислительный модуль для облака точек (~1–2 млн точек): сегментация плоскостей, поиск стен, замыкание контуров, проёмы.
- Мастер импорта: Файл → Обработка → Проверка (сомнительные места с уверенностью) → Параметры. При неудаче: подложка для обводки или пустой проект.

## 2026-11-01 · Импорт из Remplanner — только через их открытый экспорт

Свой парсер закрытого формата `.plan` не пишем (clean room). Перенос проекта возможен через файлы, которые Remplanner выгружает сам (DXF, glTF), и через подложку-изображение.

## 2026-11-01 · Лицензия: AGPL-3.0 + MIT для формата

- Приложение и ядро: AGPL-3.0.
- Схема формата `.oplan` и SDK для работы с ним: MIT.
- Разрешены зависимости под MIT/Apache/BSD/MPL/LGPL/GPL-3.0+. Запрещены GPL-2.0-only (например, LibreDWG).

## 2026-11-01 · Платформа: Tauri 2 + веб-UI + Rust-ядро

- Оболочка: Tauri 2 (macOS, Windows, Linux).
- Интерфейс: TypeScript, веб-фреймворк (выбор отдельно), холст на WebGL2, WebGPU там, где он доступен.
- Ядро на Rust: модель, геометрия, распознавание скана, экспорт (PDF, DXF, XLSX, IFC). В десктопе работает нативно и многопоточно, для веб-версии собирается в WASM.

Следствия:
- Фронтенд не зависит от Tauri напрямую, а работает через тонкий слой платформы. Если вебвью на Linux (WebKitGTK) станет проблемой, можно перейти на Electron без переписывания фронта и ядра.
- Фотореалистичный рендер позже можно вынести в отдельный нативный процесс.

## 2026-11-01 · Основной стиль UI — плотный

Один плотный интерфейс (в духе Figma и Linear) на все режимы. Отдельный «дружелюбный» режим не делаем. Онбординг строим на пустых состояниях, подсказках в статус-строке и стартовом экране.

## 2026-11-01 · Стадии вместо MVP

Работа идёт стадиями (см. `product-spec.md`). Каждая стадия доводится до рабочего состояния. Урезанного MVP нет.
